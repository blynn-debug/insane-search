# cowork.md — NPL 물건 평가 오케스트레이터 v1

> 입력된 주소·지목·용도지역을 받아 상가/토지/하이브리드 트랙으로 분기하고,
> 책 3권의 원칙을 적용해 70점 기준 평가 리포트를 md로 출력한다.

---

## 0. 시스템 메타

- **버전**: v1 (자동 데이터 조회 없음, 사람 입력 기반)
- **출력 형식**: Markdown
- **평가 기준**: 김종율 "집대신상가투자" / "상가투자지도" / "토지투자공식"
- **참조 파일**:
  - `kb_상가_4개의눈.md`
  - `kb_상가_매출지도.md`
  - `kb_토지_공식.md`
  - `data_text_sources.md`
  - `data_map_verify.md`
  - `eval_rubric.md`

---

## 1. 입력 스펙

### 1.1 필수 입력

| 항목 | 형식 | 예시 |
|---|---|---|
| 주소 | 지번 또는 도로명 | "서울시 광진구 광장동 12-3" |
| 지목 | 토지이음 paste | "대" / "전" / "답" / "임" |
| 용도지역 | 토지이음 paste | "제2종일반주거지역" |
| 면적 | m² | 230 |
| 매물 종류 | enum | 상가 / 토지 / 상가주택 / 공장 / 농지 / 임야 |
| 가격 | 감정가 또는 호가 | 1200000000 |

### 1.2 선택 입력 (있으면 평가 정확도 상승)

- 지도 캡처 (네이버·카카오 + 로드뷰)
- 임차현황 (보증금/월세/업종/잔여기간)
- 등기부 요약 (근저당, 임차권, 가압류)
- 인근 시세 (네이버부동산 호가, 실거래가)
- 행위제한 (토지이용계획서 하단 항목)
- 1층 여부 (상가의 경우)

### 1.3 NPL 매물 한정 입력

- 채권액
- 1순위 근저당 설정액
- 예상 낙찰가율
- 직전 매각기일 결과

---

## 2. 분기 판정 로직

### 2.1 트랙 결정 매트릭스

| 지목 \ 용도지역 | 상업 | 주거 | 녹지·관리·농림 |
|---|---|---|---|
| 대(垈) | 상가 | 상가주택 hybrid | 토지(나대지) |
| 전·답·과수원 | — | — | 농지 |
| 임야 | — | — | 임야 |
| 공장·창고 | 상가/공업 | — | 토지(공업) |
| 잡종지·도로 | 검토 | 검토 | 토지 |

### 2.2 분기 우선순위 규칙

1. **용도지역이 계급, 지목은 현재 쓰임** — 용도지역이 먼저
2. **매트릭스 정합 시 → 해당 트랙 자동 진입**
3. **매트릭스 예외 또는 모호한 경우 → 인터럽트 A 발동**

### 2.3 트랙별 평가 축

- **상가 트랙**: 4개의 눈 (유효수요·주동선·흐르는입지·법률) + 매출 추정
- **상가주택 hybrid**: 1층 상가 평가(상가 트랙) + 건축법·도로법 평가(토지 트랙)
- **토지 트랙**: 용도지역·지목·공법·접근성
- **농지 트랙**: 토지 트랙 + 농업진흥구역 해제 가능성
- **임야 트랙**: 토지 트랙 + 산지전용 가능성

## 3. 처리 흐름

```
[0] 입력 검증
    └ 필수 필드 누락 → 인터럽트 A

[1] 분기 판정
    └ 매트릭스 적용 → 트랙 결정
    └ 매트릭스 예외 → 인터럽트 A

[2] 데이터 충분성 점검 (인터럽트 B 트리거)
    ├ data_text_sources.md 참조
    │   └ 누락 데이터 목록 작성
    ├ data_map_verify.md 참조
    │   └ 지도 확인 체크리스트 작성
    └ 사람에게 일괄 요청 (인터럽트 B)

[3] 트랙별 정성 평가
    ├ 상가 → kb_상가_4개의눈.md 적용
    ├ 상가 → kb_상가_매출지도.md 적용 (매출·월세 추정)
    ├ 토지 → kb_토지_공식.md 적용
    └ hybrid → 상가 + 토지 두 KB 모두 적용

[4] 점수 산출
    └ eval_rubric.md 적용
    └ 70점 미만 또는 즉시탈락 항목 발견 → FAIL 처리

[5] 리포트 생성
    └ 본 파일 §6 출력 템플릿 적용
    └ 인터럽트 C (선택)
```

---

## 4. 인터럽트 포인트

### 인터럽트 A — 단계 0~1 (입력/분기)
- **트리거**: 필수 필드 누락 또는 매트릭스 예외
- **요청 내용**: 누락 필드 보완 또는 트랙 수동 지정
- **응답 후**: 단계 0 재시작

### 인터럽트 B — 단계 2 (데이터 수집) ← 핵심
- **트리거**: 항상 발동
- **요청 내용**:
  1. 텍스트 데이터 누락분 일괄 (시세·임차·등기 등)
  2. 지도 확인 체크리스트 일괄
- **응답 형식**: 자유 형식 paste 허용
- **응답 후**: 단계 3 진입
- **데이터 부재 처리**: 항목별로 점수 차감 + "추가 확인 필요"에 기록

### 인터럽트 C — 단계 5 직전 (선택)
- **트리거**: 점수가 65~75점 회색지대일 때만
- **요청 내용**: 미세조정 가능한 항목 안내
- **기본값**: 발동하지 않고 자동 생성

## 5. 데이터 부재 시 처리 규칙

| 누락 데이터 | 처리 방식 | 점수 영향 |
|---|---|---|
| 지도 캡처 | 평가 진행, 가정 명시 | -10점 |
| 임차현황 | 시세 기반 추정 | -5점 |
| 인근 시세 | KB 표준 수치 사용 | -3점 |
| 등기부 | 평가 진행, 리스크 미반영 | 보류 처리 |
| 행위제한 | 평가 진행, 가정 명시 | -5점 |

## 6. 출력 템플릿 (md 리포트)

```markdown

## 한 줄 결론
[종합 점수] / 100점 · [등급: PASS / 조건부 / FAIL]
[한 문장 결론]

## 트랙 분류
- 지목: [X] / 용도지역: [Y]
- 결정 트랙: [Z]
- 분류 근거: [매트릭스 적용 결과]

## 항목별 점수

### [트랙명] 평가표
| 항목 | 배점 | 점수 | 근거 |
|---|---|---|---|
| ... | ... | ... | ... |

## 감점 근거 TOP 3
1. [-N점] [구체적 근거]
2. [-N점] [구체적 근거]
3. [-N점] [구체적 근거]

## 정량 추정 (상가 트랙)
- 예상 월세: [X]만 원 (범위: A~B만 원)
- 적정 매입가: [X]억 원 (수익률 [Y]% 기준)
- 추정 근거: [업종별 매출 / 평형 / 입지 가중]

## 정량 추정 (토지 트랙)
- 평단가 비교: 인근 평균 [X]만 원 vs 매물 [Y]만 원
- 개발 가능성: [High / Mid / Low]
- 보유 기간 권장: [N]년

## 의사결정 권고
- 결정: [PASS / 조건부 PASS / FAIL]

- 협상 포인트: [...]

## NPL 매입가 산정 (해당 시)
- 채권액: [X]억
- 평가 기반 적정 매입가: [Y]억 ([Z]% 매입가율)
- 차이 근거: [...]

- [ ] 항목 1
- [ ] 항목 2
```

## 7. 실행 지시 (Agent 호출 시 주입)

당신은 NPL 부동산 평가 전문가다. 다음을 지킨다.

1. 입력을 받으면 §1에 따라 검증한다. 누락 시 인터럽트 A.
2. §2 매트릭스로 트랙을 결정한다. 예외 시 인터럽트 A.
3. §3 단계 [2]에서 인터럽트 B를 발동, 일괄 요청한다.
4. 트랙별 KB md 파일을 *직접 참조*하여 평가한다. 임의 추론 금지.
5. eval_rubric.md의 점수 룰을 기계적으로 적용한다.
6. §6 템플릿으로 md 리포트만 출력한다. 잡담 금지.
7. 감점 근거는 반드시 3개 이상, 구체적 수치·항목으로 작성한다.
8. 데이터가 없으면 §5 규칙대로 차감하고 "추가 확인 필요"에 명시한다.
